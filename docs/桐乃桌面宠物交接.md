# 桐乃桌面宠物交接

桐乃应当在 Codex 开始执行任务时立刻坐下打字。每打字约 60 秒，暂停 5 秒做一次坐姿思考，再继续打字。只要还有一个会话在执行，就继续这个周期。最后一个会话完成、失败或被取消后，退出工作状态。工作动作全程静音。

## 原生浮窗为什么会提前站起来

原生播放器使用 V2 图集。第 7 行是打字，第 0 行是站立待机，行号从 0 开始。浮窗的两个渲染入口都未提供播放器已有的 `loop` 参数。默认时序将第 7 行播放三次，每次 5 × 120 ms 加 220 ms，共 2460 ms。此后在同一个运行状态内，播放器继续循环使用第 0 行，其帧序列和时长与真正的待机相同。用更长的 WebP 或改写任务行，仍然无法控制浮窗此时取哪一行。

本次使用已安装的 `app.asar` 做只读诊断。默认时序在 2459 ms 仍读取第 7 行，从 2460 ms 起读取第 0 行。传入 `loop=true` 时，读取实际播放器函数测得 60 秒、65 秒、250 秒仍取第 7 行。该参数属于客户端调用，宠物清单可安装图集和名称等元数据。尚未找到通过公开的宠物配置加载播放逻辑的入口。 [宠物官方文档](https://learn.chatgpt.com/docs/pets)

## 代码和素材

- `pet/pet.json` 和 `pet/spritesheet.webp` 是原生安装包。图集为 1536 × 2288，8 列 11 行，单格为 192 × 208 像素。当前安装与 `laptop-glance-2026-11-20` 一致。
- `runtime/session-activity.mjs` 用 `turn/started`、`turn/completed` 和 `thread/status/changed` 聚合会话。接入时可以用包含最新运行轮次的快照初始化。宿主在重连后应重新读取快照。
- `runtime/thinking.css` 读取 `data-kirino-session-active` 控制 65 秒周期。会话状态由宿主提供。活动期间的站立取帧、鼠标移动、通知亮灭和已经过去的时间均不应被用作任务结束信号。
- `runtime/laptop-typing.webp` 和 `runtime/laptop-thinking.webp` 是透明且无音轨的工作素材。打字、思考的接缝共用一帧。 `previews/laptop-task-silent.gif` 可直接看敲击、思考、继续敲击的接缝。GIF 预览过渡段采用 50 帧每秒。
- `source/build_laptop_session.py` 用六个已保存的姿势重建素材。输出的思考 WebP 有 150 帧，首尾都与打字的起始帧逐像素一致。动作帧写入 `build/laptop-session/`，该目录供构建和检查使用。
